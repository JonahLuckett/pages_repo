Exercise 1
Package Checker
Ask the user for a software package name and check if it looks suspicious
Background

At IBM we use thousands of open source software packages - things like requests, numpy, flask. Before a package is used, the SLSS team checks it is safe and properly licensed.

One of the first things to check is the package name itself. Attackers sometimes publish fake packages with names very close to popular ones - for example colourama instead of colorama. If a developer accidentally installs the fake one, it can run malicious code on their machine. This attack is called typosquatting.

Learn more Typosquatting in software is well documented. The broader concept is described at en.wikipedia.org/wiki/Typosquatting. For Python-specific examples search "Python typosquatting PyPI".

Create a new file called checker.py and work through the steps below.

Exercise 2
License Checker
Read a list of packages from a file and flag any with missing or incomplete licenses
Background

Every open source software package has a license - a legal document that says how you are allowed to use it. Some licenses are very permissive (like MIT), some have conditions attached (like GPL), and some are not allowed at IBM at all.

The tools that scan packages sometimes return incomplete licenses - just "GPL" instead of "GPL-2.0-only", or a completely blank license. This is a real problem: an analyst might assume the license has been checked when it hasn't.

Learn more - SPDX license identifiers SPDX (Software Package Data Exchange) is the standard IBM uses to identify licenses. Every valid license has a unique identifier like Apache-2.0, MIT, or GPL-3.0-only. Just writing "GPL" or "BSD" is not enough - the version matters. Full list: spdx.org/licenses

Version Sorter
Sort a list of software versions into the correct order
Background

Software packages use version numbers like 1.0.0, 2.3.1, or 1.10.0. The format is usually major.minor.patch. The team needs to know the newest version of a package to make sure they are not using something out of date.

There is a catch with Python: if you sort version numbers as text, "1.10.0" can appear in the wrong position - because Python compares letter by letter. You are going to write a function to fix this.

Learn more - semantic versioning Most open source packages follow a standard called Semantic Versioning (SemVer). The format is MAJOR.MINOR.PATCH. A new major version (e.g. 2.0.0) usually means breaking changes. A new patch (e.g. 1.0.1) usually means a small bug fix. Read more: semver.org

Copyright Finder
Search license files for copyright lines and save them to a report
Background

Inside every open source license file there are copyright lines - statements like Copyright (c) 2023 Jane Smith. The SLSS team must collect these for legal records whenever they clear a package for use.

There is a known bug in the team's Bulk Clearance Tool: it only picks up the first copyright line it finds in a license file. Some packages have two or three copyright holders, and the rest are being silently dropped. This is one of the most discussed bugs in the team's issue tracker.

Learn more - why copyright matters in open source When you use open source software, you are legally required to credit the original authors in certain situations - especially when distributing software. This credit comes from the copyright lines in the license file. Dropping any of them is a legal compliance risk. Background reading: opensource.org/licenses
